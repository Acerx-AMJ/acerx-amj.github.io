3D Software rasterizer

Daniel Vishnevsky

About

Small CPU-based 3D software rasterizer featuring textures, depth buffer, near plane clipping and basic fog and lighting

Development

I started developing this project in February of 2026 under a differnt name - 3D engine. Due to an upcoming game jam (didn't participate in the end), I decided to give Lua and Love2D a try and the first project idea to pop up in my head was a 3D engine. Because it's the best project to make when you have no idea how to use a library (although, I had a lot of prior Lua experience).

And since it originally wasn't a software rasterizer, it drew 3D geometry using 2D triangles. It used math to convert the 3D points to 2D and do all kinds of other stuff (like rotate and move the geometry in 3D space). It was super basic and couldn't sort triangles properly since it was using the painter's algorithm. And it couldn't handle textures, lighting and fog like the current software rasterizer can.

But in November of 2026 I came back to this project to give it a massive overhaul and turn it into something more interesting - a software rasterizer. Now, instead of using triangles to draw geometry, it uses pure pixels. And since it uses pixels, it unlocks a plethora of cool things that can be done to it.

Firstly, I played around with the triangle weights to create the rainbow triangle (you probably know this from OpenGL), after that I implemented the UVs, which are responsible for mapping the texture to the screen. And textures were the next step. Rendering 3D textured geometry only using the CPU was mind-blowing to me.

But I didn't stop there, I implemented the near plane clipping (which was the hardest feature for me to implement, I just couldn't grep it at first) and the depth buffer (a nice break after the near plane clipping). Played with FFI optimizations and corrupted my textures (oops). And ended it off with fog and per-triangle lighting.

I love this project. I was joking to my friends about implementing Half Life 3 in it. It uses upscaled 200x200 resolution. It can handle more but I wanted everyone to be able to try it out out of the box. And it's single-threaded. But whatever, it runs at like 400-500 FPS on my integrated graphics for this simple scene. Source is on Github.
