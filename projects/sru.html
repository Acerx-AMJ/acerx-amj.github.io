About

Simple Raylib Utility Library - based on utilities developed for Sandbox-2D and AA3. Made to reduce boilerplate for different Raylib projects.

#include "SRU/sru.hpp"

int main() {
   SetConfigFlags(FLAG_WINDOW_RESIZABLE | FLAG_VSYNC_HINT);
   InitWindow(800, 600, "SRU-Lib");

   while (!WindowShouldClose()) {
      BeginDrawing();
      drawTextResponsive(GetFontDefault(), {0.5f, 0.5f}, "Hello, SRU-Lib!", 125.0f);
      EndDrawing();
   }
   CloseWindow();
}

That is not pseudo-code and it doesn't leave anything out of it. That's how easy Raylib + SRU-Lib is to use. That's the main goal of this library.

Features

This library is not supposed to replace Raylib, but to be used alongside it. And for that reason it is easily integratable with Raylib. It features standard boilerplate managers such as asset, audio and particle manager.

There are super handy utilities, like file functions for easily saving game's config and data. And utilities for parsing these values to integers, vectors, arrays and even key, value pairs. There are also handy wrappers for random numbers (both C's rand and C++'s <random> header) and various string operations, like trimming, splitting, joining and etc.

However, this library is mostly focused on the rendering part, making it extremely easy to make responsive UI and positioning elements only using constants. SRU-Lib also provides easy tweens and animations.

Animated Demon

Save the demon sprite as "demon.png" in the same directory as the cpp file. This example not only shows how to render and animate sprites, but also how to make sprites responsive. The demon sprite will be sized accordingly to the screen size.

#include "SRU/sru.hpp"

int main() {
   SetConfigFlags(FLAG_WINDOW_RESIZABLE | FLAG_VSYNC_HINT);
   InitWindow(800, 600, "SRU-Lib");

   AnimationID animationId = pushAnimation({loadTexture("demon", "demon.png"), 128, 1, 0, 2, 0.1f, true});
   Animation animation (animationId);

   while (!WindowShouldClose()) {
      animate(animation, GetFrameTime());
      
      BeginDrawing();
      ClearBackground(BLACK);
      drawTextureAnimatedResponsive(animation, {0.5f, 0.5f, 1.0f, 1.0f}, CENTER, WHITE, WINDOW_AREA, CUBIC_RATIO);
      EndDrawing();
   }
   CloseWindow();
}

Player Controller

#include "SRU/sru.hpp"

constexpr float SPEED = 250.0f;
constexpr float ACCELERATION = 1000.0f;
constexpr float DECELERATION = 2000.0f;

int main() {
   SetConfigFlags(FLAG_WINDOW_RESIZABLE | FLAG_VSYNC_HINT);
   InitWindow(800, 600, "SRU-Lib");

   Vector2 position = getWindowCenter();
   Vector2 velocity = V2();

   while (!WindowShouldClose()) {
      Vector2 direction = V2(IsKeyDown(KEY_D) - IsKeyDown(KEY_A), IsKeyDown(KEY_S) - IsKeyDown(KEY_W));
      Vector2 target = Vector2Normalize(direction) * SPEED;
      float acceleration = (direction.x != 0.0f && direction.y != 0.0f ? ACCELERATION : DECELERATION);
      velocity = Vector2MoveTowards(velocity, target, acceleration * GetFrameTime());
      position += velocity * GetFrameTime();

      BeginDrawing();
      ClearBackground(BLACK);
      drawRect(position, V2(50.0f));
      EndDrawing();
   }
   CloseWindow();
}

Development

I originally made this library because while making Sandbox-2D I noticed the amount of origin and positioning boilerplate and the lack of utilities for creating responsive layouts (my game really only worked on 1920x1080 screens) and so I created a separate header for all of these utilities. Some point later, I remembered CX and Astral Surge development cycle, where I switched from one to the other. It was fun.

And so, I decided to relive it and create a handy library for simplifying the development for future projects. And, in fact, I did relive my previous dream and it was all fun (except for restructuring the whole Sandbox-2D's source code for SRU-Lib. That was hell). While there are missing utilities, I think that it is a successful library.

You can include it with CMake's FetchContent module (there's an example) and it's fully documented. Source code is available on Github.
