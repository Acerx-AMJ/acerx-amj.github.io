Responsive Design 2

Daniel Vishnevsky

Motivation

I was working on my utility library for Raylib - SRU-Lib - and had to design the render utility with responsive design in mind. But you see, I was still using my old method of using product of screen position and ratio of window size to developer's window size. I hope you see the issue here. While it works, you have to define the screen size of your window and hope that all other developers have the same screen size. Not something to include in a public library!

But there's a way better and simpler approach (I have no idea how this didn't come to my mind at the come-to-Jesus-moment for Sandbox-2D) - just use a ratio and multiply the window size by it.

Code here is written in C++ and uses the Raylib graphics library but you can definitely adjust it for any programming language and graphics library. Luckily, Raylib is simple to use.

Implementation

It's extremely simple to create a ratio function. But you 100% will also need cubic ratio, where we use the minimum size of the window instead. And, based on your use case, might also need fill ratio, which uses the maximum instead, although not as common.

We use ratio for scaling any position to work on all screen sizes. Cubic ratio is used for both elements that should preserve aspect ratio and elements that should not overflow from their container, like text and basically any sprite. Fill ratio is the opposite of cubic ratio and it's used for things that should overflow, primarily backgrounds.

Let's implement all three! If you don't want to and are using Raylib, SRU-Lib already has all of them and a lot more. And let's use an enum so we don't have to implement thrice as many functions:

enum RatioType: char {
   RATIO, CUBIC_RATIO, FILL_RATIO
};

Since we're implementing all three functions, we first need two little helper functions to get the right size based on ratio type:

Vector2 getSizeFromRatioType(float width, float height, RatioType type) {
   if (type == CUBIC_RATIO) {
      float minimum = fminf(width, height);
      return Vector2{minimum, minimum};
   }
   else if (type == FILL_RATIO) {
      float maximum = fmaxf(width, height);
      return Vector2{maximum, maximum};
   }
   else {
      return Vector2{width, height};
   }
}

And a helper for defining your own area:

constexpr inline Rectangle WINDOW_AREA = {0, 0, 0, 0};

Rectangle getArea(Rectangle area) {
   return (area.x == WINDOW_AREA.x && area.y == WINDOW_AREA.y && area.width == WINDOW_AREA.width && area.height == WINDOW_AREA.height ? Rectangle{0, 0, (float)GetScreenWidth(), (float)GetScreenHeight()} : area);
}

Area is the container in which we want to place an element, usually it's just the window (that's why when you pass in WINDOW_AREA you'll receive the window boundaries). But oftentimes you want a sub-container like an UI frame or a scrollframe, or maybe even to use an area as a grid.

Alright, you probably get everything now, let's go over to the real deal! Although, if you didn't quite get something feel free to send an email to me and I'll try my best to clarify, it's down below in the footer. There are three functions you certaintly need. And a few you might or might not have a use case for. Really it's up to you:

Vector2 mapRatioToArea(Vector2 ratio, Rectangle area, RatioType type) {
   Rectangle realArea = getArea(area);
   Vector2 size = getSizeFromRatioType(realArea.width, realArea.height, type);
   return ratio * size + Vector2{realArea.x, realArea.y};
}

Vector2 mapSizeRatioToArea(Vector2 ratio, Rectangle area, RatioType type) {
   Rectangle realArea = getArea(area);
   Vector2 size = getSizeFromRatioType(realArea.width, realArea.height, type);
   return ratio * size;
}

float getFontSizeScaled(float fontSize) {
   return fontSize * fminf(GetScreenWidth(), GetScreenHeight()) / 1000.0f;
}

The names are self-describing. mapRatioToArea maps a positional ratio, whereas mapSizeRatioToArea maps a size ratio, hence we don't add the position of the area there. But it might not be that obvious what's going on in getFontSizeScaled - we multiply by a cubic ratio (just look at our getSizeFromRatioType function) and then divide it by 1000 since we just multiplied it by the width/height of the screen. The magic number here doesn't matter, just adjust to the new font size that fits all screen sizes.

Optionals

Lastly, I'd like to give you two optional functions - one for creating areas and one for converting ratios, since those proved to be useful in my own game, but they might or might not be useful to everyone.

Rectangle mapRatioToArea(Rectangle ratio, Vector2 origin, Rectangle area, RatioType type) {
   Rectangle realArea = getArea(area);
   Vector2 position = mapRatioToArea(Vector2{ratio.x, ratio.y}, realArea, RATIO);
   Vector2 size = mapSizeRatioToArea(Vector2{ratio.width, ratio.height}, realArea, type);
   return Rectangle{position.x - size.x * origin.x, position.y - size.y * origin.y, size.x, size.y};
}

Simple function, we just combine our two previous functions. It's important that we pass RATIO to mapRatioToArea not type. Position should almost always use the regular ratio. And there's one more little thing that is super useful here - origin. You pass an origin in range [0; 1] on both axes and it offsets the rectangle by it. If you want a centered rectangle and pass a ratio of Vector2{0.5f, 0.5f} (center of the screen) then just pass an origin of Vector2{0.5f, 0.5f} (center of the rectangle). For clarity it might be best to use these constants for origin:

constexpr inline Vector2 TOP_LEFT = {0.0f, 0.0f};
constexpr inline Vector2 TOP_CENTER = {0.5f, 0.0f};
constexpr inline Vector2 TOP_RIGHT = {1.0f, 0.0f};
constexpr inline Vector2 CENTER_LEFT = {0.0f, 0.5f};
constexpr inline Vector2 CENTER = {0.5f, 0.5f};
constexpr inline Vector2 CENTER_RIGHT = {1.0f, 0.5f};
constexpr inline Vector2 BOTTOM_LEFT = {0.0f, 1.0f};
constexpr inline Vector2 BOTTOM_CENTER = {0.5f, 1.0f};
constexpr inline Vector2 BOTTOM_RIGHT = {1.0f, 1.0f};

And lastly, something bigger. Ratio conversion from one type to another. Why, you might ask? If you have a size in cubic ratio and want to offset a regular ratio by half of that, then you're in big trouble! You can't just subtract one from another, you must convert it!

But luckily for you, I did my homework here and found this correlation between aspect ratio and different ratio types:

Axis Aspect Ratio Ratio Cubic Ratio Fill Ratio
X >1 x x * aspect ratio x
Y >1 x x x / aspect ratio
X <1 x x x * aspect ratio
Y <1 x x / aspect ratio x

Using this table, implementation looks something like this:

float convertRatioX(float ratio, RatioType type, RatioType target, Rectangle area) {
   Rectangle realArea = getArea(area);
   float aspectRatio = realArea.width / realArea.height;

   if (aspectRatio > 1.0f) {
      if ((type == RATIO || type == FILL_RATIO) && target == CUBIC_RATIO) {
         return ratio * aspectRatio;
      }
      else if (type == CUBIC_RATIO && (target == RATIO || target == FILL_RATIO)) {
         return ratio / aspectRatio;
      }
   }
   else if (aspectRatio < 1.0f) {
      if ((type == RATIO || type == CUBIC_RATIO) && target == FILL_RATIO) {
         return ratio * aspectRatio;
      }
      else if (type == FILL_RATIO && (target == RATIO || target == CUBIC_RATIO)) {
         return ratio / aspectRatio;
      }
   }
   return ratio;
}

float convertRatioY(float ratio, RatioType type, RatioType target, Rectangle area) {
   Rectangle realArea = getArea(area);
   float aspectRatio = realArea.width / realArea.height;

   if (aspectRatio > 1.0f) {
      if ((type == RATIO || type == CUBIC_RATIO) && target == FILL_RATIO) {
         return ratio / aspectRatio;
      }
      else if (type == FILL_RATIO && (target == RATIO || target == CUBIC_RATIO)) {
         return ratio * aspectRatio;
      }
   }
   else if (aspectRatio < 1.0f) {
      if ((type == RATIO || type == FILL_RATIO) && target == CUBIC_RATIO) {
         return ratio / aspectRatio;
      }
      else if (type == CUBIC_RATIO && (target == RATIO || target == FILL_RATIO)) {
         return ratio * aspectRatio;
      }
   }
   return ratio;
}

Vector2 convertRatio(Vector2 ratio, RatioType type, RatioType target, Rectangle area) {
   return Vector2{convertRatioX(ratio.x, type, target, area), convertRatioY(ratio.y, type, target, area)};
}

Usage

Here's a tiny example of how I use some of these functions in practice:

constexpr inline Vector2 buttonSize = {0.194f, 0.065f};
constexpr inline Vector2 rawButtonPadding = {0.019f, 0.019f};
constexpr inline Vector2 buttonPadding = {buttonSize.x + rawButtonPadding.x, buttonSize.y + rawButtonPadding.y};
         
Vector2 bsize = mapRatioToArea(buttonSize, WINDOW_AREA, CUBIC_RATIO);
Vector2 padding = convertRatio(buttonPadding, CUBIC_RATIO, RATIO);
float worldButtonStartY = 0.58f - convertRatioY(0.619f / 2.0f, CUBIC_RATIO, RATIO) + padding.y * 0.6f;

for (int i = 0; i < buttonsInWorldFrame; ++i) {
   worldFrameButtonRects[i] = mapRatioToArea(R4(0.5f, worldButtonStartY + padding.y * i, 1.0f, buttonSize.y), TOP_LEFT, WINDOW_AREA, CUBIC_RATIO);
}
